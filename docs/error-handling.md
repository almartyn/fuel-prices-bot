# Обробка помилок

Головне правило: **краще не опублікувати нічого, ніж опублікувати неправильні ціни.** Про будь-яку проблему бот повідомляє адміну в особисті повідомлення.

## Види збоїв і реакція

| Ситуація | Що робимо |
|---|---|
| Сайт не відповідає, таймаут, помилка 5xx | Повторюємо до `HTTP_RETRIES` разів з паузою 2 с → 4 с → 8 с. Якщо не допомогло — джерело вважається впалим. |
| Сайт повернув 403 / 429 (блокування) | Один повтор через 10 с. Потім джерело вважається впалим. |
| Сторінка завантажилась, але ціни не знайдено (змінилась верстка) | Джерело вважається впалим, в тексті помилки — яких саме селекторів не знайдено. |
| Невідома назва пального | Позиція пропускається, попередження в лог. Решта цін мережі публікується. |
| Ціна поза межами `PRICE_MIN`–`PRICE_MAX` | Позиція пропускається, сповіщення адміну. |
| Зміна за день більша за `MAX_DAILY_CHANGE_PCT` | Позиція пропускається, сповіщення адміну з обома значеннями. Ймовірно, парсер взяв не те число. |
| Частина джерел впала | Публікуємо пост з тим, що є, у пості — рядок «Не вдалося отримати дані: …». Сповіщення адміну. |
| Впали всі джерела | Пост **не публікуємо**, знімок не зберігаємо, сповіщення адміну, скрипт завершується з кодом 1 (запуск у GitHub Actions стає червоним). |
| Telegram повернув помилку при публікації | Один повтор. Якщо не вдалося — знімок **не зберігаємо** (щоб при повторному запуску порівняння було правильним), код виходу 1. |
| Telegram повернув 429 (Too Many Requests) | Чекаємо `retry_after` секунд з відповіді і повторюємо. |
| Помилка запису або коміту знімка | Пост уже опубліковано, тому лише сповіщення адміну. Наступного дня порівняння буде з позавчорашнім днем, у пості це буде видно. |
| Пошкоджений `latest.json` | Логуємо помилку, працюємо так, ніби попереднього знімка немає (пост без позначок змін), сповіщення адміну. |

## Ізоляція джерел

Парсери запускаються через `Promise.allSettled`, а не `Promise.all`. Падіння одного не зупиняє інших:

```js
const settled = await Promise.allSettled(sources.map((s) => s.fetchPrices()));

const results = [];
const errors = [];
settled.forEach((r, i) => {
  if (r.status === 'fulfilled') results.push({ source: sources[i], items: r.value });
  else errors.push({ source: sources[i], error: r.reason });
});
```

## HTTP-запити

`src/utils/http.js` обгортає `fetch`:

- таймаут через `AbortSignal.timeout(HTTP_TIMEOUT_MS)`;
- повтори з експоненційною паузою;
- заголовки звичайного браузера: `User-Agent`, `Accept-Language: uk-UA,uk;q=0.9`;
- помилка, якщо статус відповіді не 2xx, з URL і статусом у тексті.

## Сповіщення адміну

Формат:

```
🚨 fuel-prices-bot — 23.09.2026

Опубліковано: так
Не спрацювали джерела:
• SOCAR: Timeout after 20000ms (3 спроби)
• UPG: Не знайдено селектор .fuel-price

Підозрілі ціни (пропущено):
• WOG А-95: 5.69 (вчора 56.69, −90%)

Лог: <посилання на запуск у GitHub Actions>
```

Посилання на запуск у GitHub Actions будується зі змінних середовища, які GitHub задає автоматично: `${GITHUB_SERVER_URL}/${GITHUB_REPOSITORY}/actions/runs/${GITHUB_RUN_ID}`.

Якщо не вдалося надіслати і сповіщення — пишемо в лог. GitHub також надсилає email власнику репозиторію, коли scheduled workflow завершується з помилкою.

## Логи

- Кожен крок пише в `stdout` короткий рядок: `[info] okko: 5 prices in 842ms`.
- На рівні `debug` — додатково сирі значення, які повернув кожен парсер.
- Токен бота ніколи не потрапляє в лог. У GitHub Actions секрети додатково маскуються автоматично.
