# Зберігання і порівняння цін

## Навіщо зберігати

Щоб показувати в пості, як змінилися ціни («▲ 0.30»), треба пам'ятати попередні значення. Оскільки скрипт запускається в GitHub Actions і після завершення нічого не лишається, дані зберігаємо у файлах у самому репозиторії та комітимо їх після кожного успішного запуску.

## Файли

```
data/
├── latest.json            # останній успішно опублікований знімок
└── history/
    ├── 2026-09-22.json
    └── 2026-09-23.json    # копія знімка за кожен день
```

- `latest.json` — те, з чим порівнюємо при наступному запуску.
- `history/` — архів. Для порівняння не потрібен, але дає змогу пізніше будувати графіки, тижневі й місячні підсумки.

## Формат знімка

```json
{
  "schemaVersion": 1,
  "date": "2026-09-23",
  "collectedAt": "2026-09-23T06:00:12.345Z",
  "postedDate": "2026-09-23",
  "stations": [
    {
      "id": "okko",
      "name": "OKKO",
      "prices": {
        "a95": 56.99,
        "a95_premium": 59.99,
        "diesel": 54.49,
        "lpg": 32.99
      }
    },
    {
      "id": "wog",
      "name": "WOG",
      "prices": {
        "a95": 56.89,
        "diesel": 54.39
      }
    }
  ],
  "failedSources": ["socar"]
}
```

| Поле | Опис |
|---|---|
| `schemaVersion` | Версія формату. Збільшуємо, якщо структура зміниться, щоб код міг коректно читати старі файли. |
| `date` | День, до якого належать ціни, за київським часом (`Europe/Kyiv`). |
| `collectedAt` | Точний час збору в UTC. |
| `postedDate` | День, коли знімок було опубліковано. Використовується для захисту від повторної публікації. |
| `stations` | Ціни по мережах, вже нормалізовані. |
| `failedSources` | Джерела, які в цей день не спрацювали. |

Ціни зберігаємо як числа з двома знаками після коми. Щоб уникнути похибок з плаваючою комою при відніманні, різницю рахуємо в копійках: `Math.round(price * 100)`.

## Алгоритм порівняння

Вхід: `previous` (вміст `latest.json` або `null`) і `current` (щойно зібраний знімок).

Для кожної мережі і кожного виду пального в `current`:

| Ситуація | Результат | Позначка в пості |
|---|---|---|
| Попередня ціна є, нова більша | `delta > 0` | `▲ 0.30` |
| Попередня ціна є, нова менша | `delta < 0` | `▼ 0.20` |
| Ціна не змінилася | `delta = 0` | `=` |
| Попередньої ціни немає (новий вид пального, мережа вчора не спрацювала, перший запуск) | `delta = null` | без позначки |

Результат порівняння:

```js
{
  date: '2026-09-23',
  previousDate: '2026-09-22',     // або null
  stations: [
    {
      id: 'okko',
      name: 'OKKO',
      fuels: [
        { code: 'a95', price: 56.99, previous: 56.69, delta: 0.30 },
        { code: 'lpg', price: 32.99, previous: 32.99, delta: 0 },
        { code: 'a100', price: 64.99, previous: null, delta: null },
      ],
    },
  ],
  averages: [
    { code: 'a95', price: 56.85, previous: 56.63, delta: 0.22, stationsCount: 4 },
  ],
}
```

### Середня ціна

Для кожного виду пального рахуємо середнє арифметичне по мережах, які сьогодні повернули ціну. Щоб середнє було чесним, для `delta` порівнюємо лише мережі, які є **і вчора, і сьогодні**. Інакше якщо вчора дешевша мережа не спрацювала, а сьогодні спрацювала, середнє «впаде» без реальної зміни цін.

### Пропуски в днях

Порівняння завжди йде з `latest.json`, тобто з **останнім успішним** знімком, а не строго з учорашнім днем. Якщо запуск кілька днів не спрацьовував, у пості буде вказано, з якою датою порівняння: «зміни відносно 20 вересня».

### Мережа вчора не спрацювала

Якщо мережі немає в `previous.stations`, але є в `current`, можна спробувати знайти її останні ціни в `history/` (до 7 днів назад). На першому етапі достатньо показати ціни без позначок змін.

## Запис

Порядок після успішної публікації:

1. Записати `data/history/<date>.json`.
2. Перезаписати `data/latest.json` тим самим вмістом.
3. У GitHub Actions — закомітити обидва файли (див. [Розгортання](deployment.md)).

Запис файлу робимо атомарно: спершу пишемо у тимчасовий файл, потім перейменовуємо. Так збій посеред запису не залишить пошкоджений JSON.

## Об'єм даних

Один знімок — приблизно 1–2 КБ. За рік — до 1 МБ. Для репозиторію це нічого, тож ротація історії не потрібна.
