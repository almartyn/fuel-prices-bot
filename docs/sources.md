## Як дослідити сайт перед написанням парсера

Для кожного сайту перевіряємо варіанти в такому порядку, від найнадійнішого до найменш надійного:

1. **Внутрішній JSON API.** Відкрити сторінку з цінами в браузері, DevTools → вкладка Network → фільтр `Fetch/XHR`, оновити сторінку. Якщо якийсь запит повертає JSON з цінами — беремо дані з нього. JSON рідко змінюється разом з дизайном, тому це найстабільніший варіант.
2. **Ціни є в HTML, який віддає сервер.** Перевірити: `curl -A "Mozilla/5.0" <url> | grep "56.99"` (підставити ціну, яку видно на сторінці). Якщо ціна знайшлась — достатньо `fetch` + `cheerio`.
3. **Ціни вбудовані в `<script>`** як JSON (наприклад, `__NEXT_DATA__` або `window.__INITIAL_STATE__`). Тоді дістаємо вміст тегу і робимо `JSON.parse`.
4. **Ціни з'являються лише після виконання JavaScript.** Тоді потрібен `playwright`: відкриваємо сторінку в headless-браузері, чекаємо на селектор і читаємо текст. Це найповільніший і найважчий варіант, використовуємо лише якщо попередні не підійшли.

Для кожного джерела записуємо, який спосіб обрано, і зберігаємо копію відповіді у `test/fixtures/` для тестів.

## Контракт парсера

Кожен файл у `src/sources/` експортує об'єкт однакової форми:

```js
// src/sources/okko.js
export default {
  id: 'okko',
  name: 'OKKO',
  url: 'https://www.okko.ua/...',
  async fetchPrices({ http }) {
    // http — таймаут і кількість спроб з конфігу, передати в getJson / getText з src/utils/http.js
    // завантажити сторінку, розібрати, повернути масив
    return [
      { rawName: 'А-95', price: 56.99 },
      { rawName: 'PULLS 95', price: 59.99 },
      { rawName: 'ДП', price: 54.49 },
      { rawName: 'Газ', price: 32.99 },
    ];
  },
};
```

Правила:

- `rawName` — назва пального точно так, як на сайті. Приведенням до єдиних кодів займається `normalize.js`, не парсер.
- `price` — число в гривнях за літр. Кома вже замінена на крапку, пробіли й «грн» прибрані.
- Якщо сторінку не вдалося завантажити або ціни не знайдено — парсер **кидає помилку** з зрозумілим текстом. Порожній масив не повертаємо: це маскує поломку.
- Парсер не знає про Telegram, збереження чи порівняння.

## Нормалізація видів пального

Мережі називають пальне по-різному, особливо преміальні види. Щоб порівнювати між днями й мережами, зводимо назви до єдиних кодів:

| Код | Показуємо в пості | Приклади назв на сайтах |
|---|---|---|
| `a92` | А-92 | зараз жодна з чотирьох мереж на сайті не публікує |
| `a95` | А-95 | OKKO `A-95`, WOG `95 Євро5-Е10`, UPG `A-95`, SOCAR `Бензин А-95` |
| `a95_premium` | А-95+ | OKKO `Pulls 95`, WOG `95 Mustang Євро5-Е10`, UPG `upg95`, SOCAR `NANO 95` |
| `a100` | А-100 | OKKO `Pulls 100`, WOG `100 Mustang Євро5-Е0`, UPG `upg100`, SOCAR `NANO 100` |
| `diesel` | ДП | OKKO `DP`, WOG `ДП Євро5`, UPG `EURO DIESEL` (у SOCAR звичайного ДП на сайті немає) |
| `diesel_premium` | ДП+ | OKKO `Pulls Diesel`, WOG `ДП Mustang+`, UPG `upgDIESEL`, SOCAR `DIESEL NANO Extro` |
| `lpg` | Газ | OKKO `SPBT`, WOG `ГАЗ`, UPG `Газ`, SOCAR `LPG` |

Назви вказано точно так, як їх має повертати парсер у `rawName` (див. нотатки по кожному джерелу). Усі мережі публікують ще й AdBlue: це не пальне, тому в словнику воно позначається як явно ігнороване (`null`) і пропускається без попередження в лог.

Реалізація — словник відповідностей для кожного джерела окремо, бо одна й та сама назва в різних мережах може означати різне:

```js
// src/core/normalize.js
const FUEL_MAP = {
  okko: { 'A-95': 'a95', 'Pulls 95': 'a95_premium', 'DP': 'diesel', AdBlue: null, /* ... */ },
  wog:  { '95 Євро5-Е10': 'a95', '95 Mustang Євро5-Е10': 'a95_premium', AdBlue: null, /* ... */ },
};
```

Якщо назва не знайдена в словнику, пишемо попередження в лог і пропускаємо цю позицію. Так новий вид пального на сайті не зламає пост, а ми побачимо в логах, що словник треба доповнити.

## Етика і правила використання

- Один запит на джерело на день — навантаження на сайти мізерне.
- Використовуємо реалістичний заголовок `User-Agent` і не обходимо захист агресивно.
- Перед реалізацією перевіряємо `robots.txt` і умови використання кожного сайту.
- У кожному пості вказуємо джерела.

## Нотатки по джерелах

Спільне для всіх чотирьох: `robots.txt` не забороняє потрібних адрес, умови використання сайтів (там, де вони є) автоматичний збір не забороняють. Ціни на сайтах єдині по мережі, а не по конкретних АЗС (крім UPG, див. нижче). Жодне джерело не потребує Playwright. Ціни за літр, газ теж за літр.

### OKKO
- URL сторінки з цінами: https://www.okko.ua/fuels
- Спосіб отримання: внутрішній JSON API, яким користується сам сайт (Nuxt): `GET https://www.okko.ua/api/uk/fuels`. Фікстура: `test/fixtures/okko.json`.
- Шлях у JSON: `data.layout[]` → елемент з `componentName: "Global_BulletsFuel"` → `data.bullets.items[]`. У кожному елементі: `fuel_code` (стабільний код, його беремо як `rawName`), `price` (рядок `"92.90"`), `title` і `type` (`euro` / `pulls`) — лише для відображення.
- Коди: `A-95`, `Pulls 95`, `Pulls 100`, `DP`, `Pulls Diesel`, `SPBT` (газ), `AdBlue`.
- Особливості:
  - Та сама таблиця вбудована в HTML сторінок `/fuels` і головної у `window.__NUXT__`, але в стиснутому вигляді (значення підставляються через аргументи функції), тож API простіший.
  - Карта АЗС (`/fuel-map`) цін не містить — лише наявність пального на станціях.
  - Дати оновлення цін у відповіді немає. Це блок CMS, тому можливо, що його оновлюють вручну й не щодня. Варто стежити за цим після запуску.

### WOG
- URL сторінки з цінами: https://wog.ua/ua/fuels/
- Спосіб отримання: публічний JSON API `GET https://api.wog.ua/fuel_stations`. Фікстура: `test/fixtures/wog.json`.
- Шлях у JSON: `data.fuel_filters[]`. У кожному елементі: `name` (`95`, `ДП`, `100`, `ГАЗ`, `AdBlue`), `brand` (`Євро5-Е10`, `Mustang Євро5-Е10`, …; для газу й AdBlue відсутній), `price` — **ціле число в копійках** (`9290` = 92.90 грн), `id`.
- `rawName` = `name` і `brand` через пробіл, якщо `brand` є: `95 Євро5-Е10`, `ДП Mustang+`, `ГАЗ`.
- Особливості:
  - Відповідь містить також список з ~350 АЗС (`data.stations`), нам він не потрібен. Окремі станції (`/fuel_stations/<id>`) не запитуємо — одного запиту досить.
  - Ті самі ціни є в `__NEXT_DATA__` сторінки `/ua/fuels/` (`props.pageProps.initialReduxState.pageReducer.elements[1].block.items`) — запасний варіант, якщо API закриють.
  - За описом на сайті Mustang 100 має октанове число 98, але позиціонується як «100» — зводимо до `a100`.
  - `wog.ua/robots.txt` перенаправляє на `api.wog.ua/robots.txt`.

### UPG
- URL сторінки з цінами: https://upg.ua/cini-na-palne/
- Спосіб отримання: JSON у `<script>` у HTML сторінки (WordPress): `var obj = {...};`. Фікстура: `test/fixtures/upg.html`.
- Шлях у JSON: `obj.data[]` — рядки `{ RegionID, RegionName, AveragePrice, FuelTypeId, Title }`, по рядку на кожну пару «область × пальне» (21 область). `AveragePrice` — рядок `"88.90"`. `Title` беремо як `rawName`: `A-95` (латинська A), `upg95`, `upg100`, `EURO DIESEL`, `upgDIESEL`, `Газ`, `AdBlue`.
- Дата оновлення: `obj.LastDataUpdateDate` (`"2026-09-24"`). Можна використати для перевірки, що дані не застарілі.
- Особливості:
  - Ціни **по областях**, а в пості показуємо одну ціну на мережу. Ціни майже скрізь однакові (24.09.2026 відрізнявся лише `upgDIESEL`: 99.90 / 99.91 / 99.94), тому беремо найчастіше значення по всіх областях. У деяких областях окремих видів пального немає — це не помилка.
  - Об'єкт витягуємо з тексту скрипта і розбираємо `JSON.parse`, а не виконуємо як JavaScript.

### SOCAR
- URL сторінки з цінами: https://socar.ua/fuel
- Спосіб отримання: внутрішній JSON API сайту (Nuxt, формат JSON:API): `GET https://socar.ua/api/pages/fuel`. Фікстура: `test/fixtures/socar.json`.
- Шлях у JSON: `data.attributes.blocks.data[]` → блок з `id: "contentCardList"` → `attributes.items[]`. У кожному елементі: `title.text` (беремо як `rawName`) і `price` — **текст** `"*Ціна: 97.9 грн/л"` або `"*Ціна: 104 грн/л"`, число з нього дістаємо регулярним виразом.
- Назви: `Бензин А-95`, `NANO 95`, `NANO 100`, `NANO ДП`, `DIESEL NANO Extro`, `LPG`, `AdBlue`.
- Особливості:
  - Найменш надійне джерело: ціни — маркетинговий текст CMS з приміткою «Ціни можуть змінюватись. Актуальні ціни – на АЗК SOCAR», точність іноді до гривні (`104`), дати оновлення немає.
  - Звичайного ДП на сайті немає, лише преміальні `NANO ДП` і `DIESEL NANO Extro`. `DIESEL NANO Extro` зводимо до `diesel_premium` (ДП+), а `NANO ДП` пропускаємо (`null`): окремого коду для другого преміального дизеля немає.
  - Карта АЗС (`/map`) цін не містить.
